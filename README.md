# Визуальный штамп электронной подписи в PDF из 1С

Небольшой пример интеграции 1С и Python, который добавляет в уже сформированный PDF синий векторный штамп:

- статус подписания;
- отпечаток или иной идентификатор сертификата;
- владельца сертификата;
- срок действия сертификата;
- номер машиночитаемой доверенности.

Исходный PDF не преобразуется в набор изображений. Рамка и текст добавляются поверх существующих страниц,
поэтому текстовый слой и исходное качество документа сохраняются.

> Визуальный штамп не создает электронную подпись, не подтверждает ее действительность и не заменяет файл МЧД.
> Подписание и проверка подписи должны выполняться отдельным штатным или сертифицированным механизмом.

## Состав проекта

- `src/pdf_signature_stamp.py` - обработка готового PDF с помощью PyMuPDF;
- `src_1c/CommonModules/ВизуализацияПодписиPDFСервер/Ext/Module.bsl` - серверный модуль интеграции 1С;
- `examples/integration_1c.bsl` - пример точки вызова из прикладного кода;
- `examples/job.example.json` - формат задания без реальных реквизитов;
- `examples/create_demo_pdf.py` - создание локального демонстрационного PDF;
- `tests/test_pdf_signature_stamp.py` - автоматическая проверка двухстраничного документа;
- `docs/АРХИТЕКТУРА.md` - границы ответственности и последовательность обработки;
- `docs/БЕЗОПАСНОСТЬ.md` - требования к обезличиванию и публикации.

## Как работает решение

1. 1С получает адрес готового PDF во временном хранилище.
2. Серверный модуль проверяет тип файла, данные штампа и настройки окружения.
3. 1С записывает PDF и JSON-задание во временные файлы на сервере.
4. Сервер 1С запускает Python от учетной записи службы 1С.
5. Python открывает PDF, добавляет штамп и сохраняет новый файл.
6. 1С читает результат, переиспользует исходный адрес временного хранилища и удаляет временные файлы.

Реквизиты сертификата не передаются через командную строку. Это уменьшает риск их появления в списке процессов.

## Требования

- Windows на сервере, где выполняется серверный код 1С;
- Python 3.10 или новее;
- PyMuPDF версии из `requirements.txt`;
- установленный системный шрифт с кириллицей;
- право учетной записи службы 1С запускать Python и работать с временными файлами.

Пример использует `WScript.Shell`. Его доступность зависит от настроек сервера, антивируса и групповых политик.

## Установка Python и зависимости

Рекомендуется устанавливать Python для всех пользователей в отдельный каталог, доступный службе 1С.
Не используйте Python из профиля администратора: служба 1С может не видеть этот профиль и установленные в нем пакеты.

Создайте виртуальное окружение:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Проверьте установку:

```powershell
.\.venv\Scripts\python.exe -c "import pymupdf; print(pymupdf.VersionBind)"
```

Для изолированного сервера скачайте подходящий файл `.whl` на компьютере с интернетом, перенесите его на сервер
и установите полным путем:

```powershell
<ПУТЬ_К_PYTHON> -m pip install <ПУТЬ_К_ФАЙЛУ_PYMUPDF_WHL>
```

Версия Python, архитектура Windows и метка файла `.whl` должны совпадать.

## Быстрая локальная проверка

Создайте демонстрационный PDF:

```powershell
.\.venv\Scripts\python.exe .\examples\create_demo_pdf.py
```

Перейдите в каталог `examples` и выполните обработку:

```powershell
..\.venv\Scripts\python.exe ..\src\pdf_signature_stamp.py --config .\job.example.json
```

Результат появится в `examples/output.pdf`. PDF-файлы исключены из Git через `.gitignore`.

## Формат JSON-задания

```json
{
  "input_pdf": "input.pdf",
  "output_pdf": "output.pdf",
  "certificate": "0000000000000000000000000000000000000000",
  "owner": "ПОЛЬЗОВАТЕЛЬ",
  "valid_until": "31.12.2099",
  "power_of_attorney": "00000000-0000-0000-0000-000000000000",
  "pages": "all"
}
```

Допустимые значения `pages`: `all`, `first`, `last`.

Необязательные параметры геометрии:

| Параметр | Значение по умолчанию | Назначение |
|---|---:|---|
| `stamp_width_ratio` | `0.49` | Доля доступной ширины страницы |
| `stamp_height` | `100` | Высота рамки в пунктах PDF |
| `left_margin` | `40` | Отступ слева |
| `bottom_margin` | `60` | Отступ снизу |
| `font_path` | автоматический поиск | Полный путь к шрифту с кириллицей |

Скрипт автоматически уменьшает размер текста, если длинный номер не помещается в рамку.

## Подключение к 1С

Создайте в расширении серверный общий модуль `ВизуализацияПодписиPDFСервер` и перенесите в него содержимое
`src_1c/CommonModules/ВизуализацияПодписиPDFСервер/Ext/Module.bsl`.

Модуль содержит законченный независимый от метаданных сценарий:

- создание и проверку контрактов данных;
- получение и обновление PDF во временном хранилище;
- запись JSON-задания в UTF-8;
- безопасное формирование команды `cmd /C`;
- ожидание завершения Python и чтение стандартного вывода;
- диагностику установленного Python и PyMuPDF;
- удаление временных PDF, JSON и журналов;
- сохранение исходного текста ошибки при сбое очистки.

Настройте свойства общего модуля в соответствии с вашей конфигурацией и политиками безопасности сервера.
Минимально требуется серверный контекст. Вызов внешнего процесса и COM должен быть разрешен администратором.

Для формирования данных используйте публичный конструктор:

```bsl
ДанныеШтампа = ВизуализацияПодписиPDFСервер.НовыеДанныеШтампа(
	"0000000000000000000000000000000000000000",
	"ПОЛЬЗОВАТЕЛЬ",
	'20991231',
	"00000000-0000-0000-0000-000000000000");
```

Пути нужно получать из настроек вашей системы, а не хранить непосредственно в модуле:

```bsl
Настройки = ВизуализацияПодписиPDFСервер.НовыеНастройки(
	"<ПУТЬ_К_PYTHON>",
	"<ПУТЬ_К_СКРИПТУ>");
```

Проверка окружения без обработки документа:

```bsl
Диагностика = ВизуализацияПодписиPDFСервер.ПроверитьОкружение(Настройки);
Если Не Диагностика.Успешно Тогда
	ВызватьИсключение Диагностика.Сообщение;
КонецЕсли;
```

Обработка PDF по существующему адресу временного хранилища:

```bsl
АдресPDF = ВизуализацияПодписиPDFСервер.ДобавитьШтампВоВременноеХранилище(
	АдресPDF,
	ПредставлениеФайла,
	ДанныеШтампа,
	Настройки);
```

Добавляйте визуализацию до криптографического подписания. Любое изменение уже подписанного PDF нарушит проверку
его подписи.

Используйте `examples/integration_1c.bsl` как пример точки вызова, а не как готовую замену прикладного модуля.

Вызывающий код должен передать:

- адрес готового PDF во временном хранилище;
- представление файла с расширением;
- значения сертификата и доверенности;
- полный путь к `python.exe`;
- полный путь к `src/pdf_signature_stamp.py`.

Структура `ДанныеШтампа`, создаваемая функцией `НовыеДанныеШтампа`, содержит поля:

- `ОтпечатокСертификата`;
- `ВладелецСертификата`;
- `СрокДействияСертификата`;
- `НомерДоверенности`.

Не включайте реальные реквизиты в код. Получайте их из штатного механизма подписания непосредственно перед вызовом.

## Учетная запись службы 1С

Серверный вызов выполняется не от интерактивного пользователя Windows, а от учетной записи рабочего процесса
сервера 1С. Для нее необходимо проверить:

- чтение и выполнение `python.exe`;
- чтение скрипта;
- чтение установленного системного шрифта;
- создание, чтение, изменение и удаление файлов во временном каталоге;
- импорт PyMuPDF именно тем интерпретатором, который указан в вызове;
- отсутствие запрета на запуск `python.exe`, `cmd.exe` и `WScript.Shell` в политиках безопасности.

Пакет нужно устанавливать через тот же интерпретатор:

```powershell
<ПУТЬ_К_PYTHON> -m pip install -r requirements.txt
<ПУТЬ_К_PYTHON> -c "import pymupdf; print(pymupdf.VersionBind)"
```

Изменения системных переменных окружения становятся видны службе только после ее перезапуска.

## Диагностика ошибок запуска

Код 1С сохраняет стандартный вывод и ошибки Python во временные файлы. Если они не создаются, проблема находится
до запуска Python. Проверяйте по порядку:

1. Может ли 1С самостоятельно создать файл во временном каталоге.
2. Может ли служба выполнить `cmd.exe /D /S /C echo test`.
3. Существует ли указанный `python.exe` и есть ли право на его выполнение.
4. Возвращает ли этот интерпретатор версию при запуске с `--version`.
5. Импортируется ли `pymupdf` именно этим интерпретатором.
6. Доступны ли входной PDF, JSON-задание и системный шрифт.

Ошибка `The filename, directory name, or volume label syntax is incorrect` обычно означает неверное экранирование
команды `cmd /C`. В примере эта логика вынесена в функцию `ВКавычках`, а вся внутренняя команда заключена
в дополнительную пару кавычек.

Ошибка `encoding problem: cp1251 with BOM` возникает, когда файл фактически записан в UTF-8 с BOM, но объявлен
как `cp1251`. В этом проекте Python-скрипт является постоянным UTF-8-файлом, а JSON читается как `utf-8-sig`,
поэтому наличие BOM в JSON не мешает обработке.

## Проверка

Запуск автоматического теста:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тест создает временный двухстраничный PDF, добавляет штамп на обе страницы и проверяет наличие текста.

Файл BSL поставляется как исходный код общего модуля, а не как полный проект расширения EDT. После переноса
в рабочее расширение выполните проверку конфигурации и тестовый вызов под учетной записью службы сервера 1С.

## Ограничения

- Проект не создает и не проверяет криптографическую подпись.
- Проект не прикладывает XML-файл МЧД к контейнеру подписи.
- Изменение уже подписанного PDF нарушит проверку существующей подписи. Штамп нужно добавлять до подписания
  либо формировать как часть отдельно определенного процесса, согласованного с владельцем системы.
- Координаты указаны в пунктах PDF и могут потребовать настройки для нестандартных размеров страниц.
- Визуальное представление не является доказательством действительности сертификата или доверенности.

## Конфиденциальность

Репозиторий содержит только условные значения `ПОЛЬЗОВАТЕЛЬ`, нулевые идентификаторы и относительные пути.
Перед публикацией собственной версии выполните checklist из `docs/БЕЗОПАСНОСТЬ.md`.
